# Opponent Scout Hub — 開発・公開ガイド

このリポジトリには3つのフォルダがあります。役割が違うので、混同しないようご注意ください。

- **`app/`（このフォルダ）** — アプリの「元データ」（ソースコード）です。見た目や画面の中身を直すときは、必ずここを編集します。
- **`../collector/`** — ニュースを自動収集するプログラムです。**どんなニュースを集めるか**を変えたいときはこちらを編集します（詳しくは `../collector/lib/topic.mjs`）。収集結果は `app/src/data/collected/*.json` に書き出され、アプリはそれを読んで表示します。
- **`../site/`** — `app/` から自動生成される、**そのまま公開できる最終ファイル一式**です。ビルドのたびに作り直されるためGitには保存していません（`.gitignore` 済み）。**このフォルダの中身は手で編集しないでください**（次にビルドすると上書きされて消えます）。

## 自動更新の仕組み（現在の公開方法）

`.github/workflows/collect-and-deploy.yml` が、GitHub Actions 上で**1日3回（日本時間のおおよそ 09:00 / 17:00 / 01:00）**自動実行されます。処理の順番は次のとおりです。

1. `collector/` がニュースを収集し、`app/src/data/collected/*.json` を更新する
2. 更新された JSON をリポジトリに自動コミットする（`[bot] update collected news data`）
3. `app/` をビルドして `site/` を作る
4. `site/` を **GitHub Pages** に公開する

つまり、**サーバーへの手動アップロードは不要**です。GitHubのActionsタブから手動実行（Run workflow）することもできます。

**初回のみ必要な設定**: リポジトリの Settings → Pages で、「Source」を「GitHub Actions」に設定してください（設定済みなら不要です）。

## 「再収集」ボタン（手動での更新）

画面右上の **「再収集」** ボタンを押すと、**その場で最新の収集結果を取り込み直します**。自動更新（1日3回）を待たずに画面を最新にできます。ページの再読み込みも不要です。

- ボタンの下の **「新しい収集を実行 ↗」** は、GitHubのActions画面を開きます。そこで「Run workflow」を押すと**収集そのものを今すぐ実行**できます（完了まで数分。終わったら「再収集」を押すと結果が反映されます）
- 2つに分かれているのは、収集の実行にはGitHubへのログイン情報が必要で、**公開ページ側にその情報を持たせるのは危険**なためです
- インターネットに繋がらない場合は「取得できませんでした」と表示され、**それまでの表示内容はそのまま残ります**（画面が空になることはありません）

## レンタルサーバー等に自分で置きたい場合

GitHub Pages を使わず自前のサーバーに置くこともできます。その場合は `npm run build`（下記）で生成される `../site/` フォルダの中身（`index.html` や `assets/` フォルダなど）を、そのままアップロードしてください。サブフォルダ（例: `example.com/scouthub/`）に置いても、ドメイン直下に置いても、どちらでも正しく表示されるように作ってあります。外部サイトへの通信（Google Fonts・国旗画像のCDNなど）は一切行わないため、それ以外の設定は不要です。

## 内容を修正したいとき

1. `app/src/` 内の該当ファイルを編集します（下記「フォルダ構成」を参照）。
2. ターミナルで以下を実行します。

   ```
   cd app
   npm install   # 初回のみ
   npm run build
   ```

3. `../site/` フォルダの中身が自動的に更新されるので、`npm run preview` で見た目を確認します。
4. 問題なければ、変更を GitHub の `main` ブランチに push します。**push すると上記のワークフローが自動で走り、公開サイトが更新されます**（手動アップロードは不要です）。

## フォルダ構成（`app/src/`）

- `data/` — 対戦国一覧、カテゴリー、監督名、信頼度ティアなど、画面に出てくる基礎データ
- `data/collected/` — **収集された本物のニュース**（`collector/` が自動生成。手で編集しないでください）
- `lib/` — 上記データを画面用に整えるロジック（`collectedData.ts` が収集済みニュースの読み込み口）
- `state/` — 画面遷移やフィルタなど、アプリの状態管理
- `components/screens/` — 画面ごとの見た目（ホーム・国別詳細・監督プロファイル・動画要約・情報源管理・更新フィード・レポート出力）
- `components/shell/` — サイドバー・ヘッダー
- `components/primitives/` — 国旗表示・タグ・バッジなど共通部品
- `styles/` — 配色・余白などデザインの基本ルール（`design-system.css`）と、紺色アクセントへの上書き（`accent-override.css`）、自前ホスティングしているフォント定義（`fonts.css`）
- `assets/flags/` — 対戦国の国旗画像（SVG、外部サイトを使わずアプリに同梱）
- `assets/fonts/` — 見出し用フォント Barlow / Barlow Condensed（同じく同梱）

## 動作確認（任意）

サーバーにアップロードする前に手元で見た目を確認したい場合は、以下でプレビューできます。

```
cd app
npm run dev
```

表示されたURLをブラウザで開くと、公開前の状態を確認できます（この方法はあくまで確認用で、公開には使いません。公開には `../site/` の中身をアップロードしてください）。
